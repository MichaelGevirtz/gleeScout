System design — reference diagram

GleeScout

An AI event-planning agent that turns a chat conversation into a short, explainable list of real local providers. The backend keeps the LLM confined to reasoning steps — extracting intent, phrasing questions, simulating answers — while deterministic code owns state, workflow, scoring, and everything that has to be trustworthy or repeatable.

Backend — TypeScript React Native Gemini (structured output) Firecrawl Zod validation In-memory only, no DB
01 — Orientation

System context

A React Native client talks to one backend process over plain HTTP/JSON. The backend is the only thing that calls out to Gemini or Firecrawl, and the only state that exists lives in that process's memory.

02 — Mechanism

Request pipeline: where the LLM proposes and where code decides

A conversation moves through four phases. In each one, the LLM is called for exactly the reasoning it's suited to — interpreting, phrasing, hypothesizing — and every one of its outputs is Zod-validated, then handed to deterministic code that owns state, merging, gating, and scoring.

03 — Data model

Three buckets that never merge

Every piece of provider data is tagged by where it came from, and the three tags are structurally kept apart rather than flattened into one object.

FACT

Directly scraped from a page: name, pricing, services, rating. Carries its source URL and retrieval time.

produced by discoverProviderCandidates()
INFERRED

A qualitative tag derived from review text ("good with toddlers"), pointing back to the evidence it came from.

produced by enrichProviderCandidates()
SIMULATED

An LLM's hypothesis about how a provider might answer a specific gap question — never a real confirmation.

produced by simulateProviderResponses(), kept off the provider object entirely

06 — Shape of the design

What the structure is protecting

The LLM proposes, code decides Extraction returns a candidate patch, not a state mutation. Merging, readiness, and which question to ask next are pure functions with no model call in the loop.
Every model output is re-validated All six Gemini call sites return JSON checked against a Zod schema before anything downstream can read it.
Research sits behind one boundary Firecrawl is reached through a small provider interface, so a different search or scraping backend is a swap, not a rewrite.
Nothing outlives the process One in-memory map keyed by session id holds all state. Restart the server and every conversation, candidate, and trace disappears — by design.
